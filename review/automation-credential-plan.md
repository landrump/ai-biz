# Automation Credential Plan

This plan defines how Listinglever credentials should be stored and used for
automation.

## Position

The user is comfortable with automation login where it increases speed. The
agent should still avoid storing secrets in GitHub, markdown docs, screenshots,
or chat transcripts when there is a safer path.

Use credentials only through:

1. Platform secret management.
2. Local `.env` files ignored by Git.
3. OAuth/MCP connections.
4. Short-lived access tokens supplied through environment variables.

Do not commit:

- Passwords.
- App secrets.
- API keys.
- Access tokens.
- Refresh tokens.
- Payout, banking, tax, or identity details.
- Recovery codes.

## Repo setup

The repository includes:

- `.gitignore` blocking `.env`, `secrets/`, `credentials/`, token files, keys,
  and common Dropbox credential files.
- `.env.example` with placeholder variable names only.

To use local credentials, copy:

```text
.env.example -> .env
```

Then fill values only in `.env` or in the cloud platform's secret manager.

## Preferred access methods by service

### Dropbox

Preferred:

1. Dropbox remote MCP OAuth in Cursor, if available.
2. Dropbox API access token in `DROPBOX_ACCESS_TOKEN`.
3. Refresh-token setup using `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, and
   `DROPBOX_REFRESH_TOKEN`.

Notes:

- Rotate any Dropbox app secret that was pasted into chat before production use.
- Use a dedicated `/Listinglever` folder.

### Google Drive

Preferred:

1. Google Drive MCP or Workspace connector if it becomes available.
2. Service account shared as Editor on the Listinglever Drive folder.
3. Apps Script upload endpoint with a secret token.

### Gumroad

Preferred:

1. Gumroad API or official integration if available for the needed action.
2. Manual product shell creation by the user, then agent supplies exact copy,
   files, and settings.
3. Browser/session automation only if permitted, stable, and not blocked by MFA.

Store:

- `GUMROAD_EMAIL`
- `GUMROAD_API_TOKEN`, if available

Do not store:

- Payout details.
- Bank details.
- Recovery codes.

### Email

Preferred:

1. SMTP/IMAP credentials for `info@listinglever.net` stored in `.env` or
   secrets.
2. Email platform API keys if using MailerLite, EmailOctopus, or another sender.

Store:

- `LISTINGLEVER_EMAIL_ADDRESS`
- `LISTINGLEVER_EMAIL_PASSWORD`
- `LISTINGLEVER_IMAP_HOST`
- `LISTINGLEVER_SMTP_HOST`

Before use:

- Change any temporary mailbox password generated by Turbify.
- Use a unique password not reused anywhere else.

### Pinterest

Preferred:

1. Pinterest API or business account access token.
2. Scheduler integration such as Tailwind/Buffer/Later.
3. Manual upload with agent-provided queue if API access is not available.

### AI image tools

Preferred:

1. `OPENAI_API_KEY` for ChatGPT Images / `gpt-image-2`.
2. `GOOGLE_AI_API_KEY` for Gemini Image / Nano Banana.

## Automation levels

### Level 0: No credential access

Agent produces copy, prompts, docs, setup packets, and upload instructions.
User uploads or publishes manually.

### Level 1: File-write access

Agent can write product files, image prompts, trackers, and launch assets to
Dropbox or Drive.

### Level 2: Product-platform access

Agent can create or update Gumroad/Etsy/Pinterest drafts when API or account
access is available.

### Level 3: Publishing access

Agent can publish externally only after the user approves:

- Product files.
- Public claims.
- Price.
- Refund/support policy.
- Any paid spend.

### Level 4: Paid marketing access

Agent can run small ad tests only after explicit budget caps and stop conditions
are recorded.

## Immediate recommended credential path

1. Change the temporary `info@listinglever.net` password.
2. Put email SMTP/IMAP settings in `.env` or platform secrets.
3. Configure Dropbox MCP or add a short-lived Dropbox token to secrets.
4. Add OpenAI and/or Google AI image API key for creative generation.
5. Keep Gumroad publishing manual until product shells are created or an API path
   is confirmed.
